# 电极 GUI 的实时 LSL 正弦台架模式

> 以下为旧 EXE 的历史说明，不适用于当前源码。新版使用仓库内 `Start_Electrode_QA.cmd`，默认 ECG、自动发现流，且不再预选 C11/C12。请看 [当前使用说明](REALTIME_POST_GUIDE.md) 和 [VS Code / Git 配置](GIT_SETUP_CN.md)。

本次已在原 Electrode QA GUI 顶部增加 **Live LSL · Sine** 入口，使用现有电极热图和3D身体示意图显示实时结果。原BDF/ZIP分析、时间轴回放和报告导出仍在原窗口。实时模式适用于已知正弦输入；本次不把正弦判定应用到人体ECG。

## 现场使用

1. 完整解压 `Electrode_QA_Live.zip`，保留 EXE 和 `_internal` 在同一文件夹。
2. 双击 `Electrode_QA_Live.exe` 打开完整GUI，点击右上角 **Live LSL · Sine**。也可以双击 `Start_Live.cmd` 直接打开实时窗口。无需安装Python。
3. ActiView开始采集后，点击 **1. Search LSL**，选择实际的ActiView流，再点 **2. Connect**。
4. 表格列出流的各个通道。默认仅勾选有准确标签的C11/C12。点击 **Use** 列增减监测通道；只选择实际接入测试信号的通道。
5. 核对实际接线和流来源，勾选 **I verified stream / physical channel mapping**。标签缺失时通过 **Map label** 明确指定该列的物理通道，不能假定第1/2列就是C11/C12。3D示意位置只识别A1–D32；其他标签保留在网格中。
6. 单位默认使用各通道的LSL元数据。缺少或不支持单位时保持黄色，只有确认数据单位/换算系数后才使用手动选项。不根据希望得到的10 mVpp反推系数。
7. 正弦测试填写实际频率和输入幅度，例如 **5 Hz、10 mVpp**。程序自动采用填写值计算增益，不再要求勾选 Vpp 确认。
8. 点击 **3. Start monitoring**。默认分析最近5秒，每1秒启动一轮新分析。初始不足5秒时显示灰色。
9. 点任一电极，底部显示它的近期波形、增益/波形/频率/THD/SNR及异常原因。**Live 3D torso** 标签页显示同一组结果；Front/Back切换身体前后，原有旋转和缩放可用。
10. **Save window + log** 保存当前选中通道的短窗口NPZ、JSON和最近状态变化。不是连续无损记录器。

## 颜色与判定

- **绿色**：该窗口内已评估的增益、波形残差、频率、THD、SNR符合当前阈值；映射/单位/输入均已确认。
- **黄色**：需要核对；可能是接近阈值、单位未知、输入未确认或某项不可评估。
- **红色**：信号通路检查未通过，例如幅值显著下降、近乎平直、频率不符、波形畸变或噪声。原因显示在详情中，不能直接推断为电极物理损坏。
- **灰色**：没有当前评估，例如未监测、窗口未满、断流、时间戳断点、停止或结果过时。断流时不会把上次的绿色当作当前正常。

红色首次出现就显示；连续两个不同窗口都红色时，详情增加 **Persistent alert**。窗口可以重叠，因此这不是两次独立实验。恢复后随新的窗口恢复颜色，不保留旧故障色。

实时接收并不等于零延迟判断。默认需要先积累5秒；之后每1秒检查最新5秒。新故障进入混合窗口后可能触发，故障消失后通常需要旧异常样本滑出窗口。SNR/THD等指标也受窗口时长影响。

默认增益限值5%、频率误差0.1%、THD 1%，黄色边界为上限的80%。SNR默认20 dB以上为绿、10–20 dB为黄、低于10 dB为红。波形残差/突变检查复用项目的配置；这些是工程检查阈值，不是经过全面校准的硬件合格标准。实时窗口的可编辑限值独立生效，改变设置会立即清除旧结果，需要重新点Start monitoring。

目前不评估硬件数字量程削顶（流中没有已核实的量程定义），不把波形畸变直接叫作硬件饱和；不同信号路径、接线、参考和输入异常都可能使通道变红。线性度、独立重复性和通道同步没有合并到实时健康色。

## 一键模拟演示

点击 **SYNTHETIC demo + amplitude fault**。这是本机真实LSL发送/接收，但数据为合成，横幅明确标为 **SYNTHETIC DEMO**。

- C11始终为5 Hz、10 mVpp。
- C12在每30秒周期的8–18秒由10 mVpp降到5 mVpp，然后恢复。
- 等待初始窗口：先灰，随后正常两路绿，C12异常时红，恢复窗口后重新绿。
- 模拟器只对自己生成的已知输入自动确认；连接真实流时确认框会重置。

## 技术结构

```text
ActiView LSL
  → services/lsl_stream.py：后台接收全部发送通道及源时间戳
  → 10秒/64 MiB有界缓冲：保留原单位数据
  → services/live_analysis.py：选中通道的完整滑动窗口
       复用 BenchSpectrumAnalyzer / AmplitudePeakGainError
       各通道独立拟合，避免坏通道污染另一通道
  → ElectrodeResult / MetricResult
  → views/live_window.py：自动更新网格、3D、原因和近期波形
```

接收线程不修改Tk控件。计算在另一个后台线程进行，最多一轮计算在运行；慢时跳到最新窗口而不堆积旧任务。结果带连接/配置版本，重连或改变配置后到达的旧结果会被丢弃。时间戳断点必须滑出窗口才继续有效判定。所有实时计算使用完整窗口，不套用离线文件“排除最后1秒”的规则。

界面波形约10次/秒刷新，状态按配置的分析步长更新；这与设备每秒1024个采样点不同。只为绘图抽取每个显示分组的最小/最大值，保存和分析使用完整采样。64 MiB缓冲不足以覆盖所选窗口时拒绝启动，需缩短窗口或降低发送采样率。

保存的 `samples_native` 为 `[采样点, 选中通道]`；明确单位时另存 `data_uv` 为 `[选中通道, 采样点]`。`timestamps_lsl` 为原始源时钟秒数。JSON保留原始流XML、通道选择/映射、单位换算、阈值、当前评估是否有效、评估窗口和保存窗口各自的时间戳、最近最多500条颜色变化。保存窗口可能比最近完成的评估窗口更新；两个时间范围分别记录，不应混为同一窗口。

## 开发者

```powershell
python -m pip install -r requirements_live.txt
python gui.py
# 或直接打开实时窗口
python live_main.py --live
# 回归测试
python -m unittest discover -s tests -v
```

依赖的LSL接收代码来自本项目已验证的 `lsl-check` 工具，随本应用放置，不需要从另一个EXE读取数据。不要把两个工具的NPZ格式或采样率默认值混用。

## 本次验证

51项自动测试通过，包括原离线功能及新增的正弦健康/幅值下降、平直、噪声、错误频率、NaN、单位/输入/映射确认、时间戳断点、持续告警、设置版本、断流清色、灰色3D、保存回读及关闭清理。

源码GUI已通过真实本机LSL模拟的“正常→幅值下降→恢复”测试。在本机对128通道、1024 Hz、5秒合成窗口单次分析约0.44秒；这是本次计算耗时测量，不代表所有电脑或真实硬件的端到端延迟。

真实ActiView连接、物理通道映射和电压标定仍需现场确认。程序能显示“哪个通道的信号需要检查”，不能单凭这些信号确定故障一定出在电极。
